# Сайт МТПК / Уралиндуктор — корневой контекст

> Карта проекта, не свалка деталей. Детали — по навигации ниже.

## Что это

Сайт uralinduktor.ru на собственной платформе `platform/`: сайт и админка на Next.js,
сервисы (контент, медиа, заявки, поиск), данные в PostgreSQL (Prisma), кеш Redis,
файлы в S3 (локально MinIO). ~1000 адресов: страницы, каталог (категории →
подкатегории → товары), запчасти, Практикум. Подробнее о проекте: docs/project-info.md.

**Работаем только локально** (решение Евгения от 07.10.2026): выкладки нет, до полной
отладки ничего не выкладываем. Старый сайт на Astro удалён из репозитория (остался в
истории git); на боевом домене пока работает он.

## Главное правило

Ищи простое решение. Не выдумывай ничего, что уже описано в документах:
стиль — style.md, структура — structura.md, типы страниц — docs/page-types/.
Не хватает информации — спроси Евгения, не фантазируй.

## Стек и локальный запуск (из `platform/`)

- Инфраструктура: `npm run infra:up` — Postgres (:5442), Redis, MinIO в Docker Desktop. Файлы сайта с 15.10.2026 —
  в TimeWeb Cloud S3 (`S3_*` в platform/.env); MinIO — только для отката (его данные — на 15.10.2026).
- Сервисы: `npm run dev` — контент :4101, заявки :4102, поиск :4103, медиа :4104, рассылки :4105 (+ отправитель писем).
- Сайт: `npm run build:web` → `npm run start -w @mtpk/web` — http://127.0.0.1:3200.
- Админка: `npm run dev -w @mtpk/admin` — адрес `/admin`: http://127.0.0.1:3300/admin, через сайт —
  http://127.0.0.1:3200/admin (на домене — uralinduktor.ru/admin). Вход — только по секретной ссылке
  `/admin/login?token=<ADMIN_LOGIN_TOKEN из platform/.env>`, без неё админка отвечает 404.
  Токен не публиковать; новый токен в .env отменяет выданные пропуска. После пароля — код 2FA, если
  пользователь включил её сам («Настройки входа» внизу меню).
- База: схема и миграции — packages/db/prisma; новая миграция — `npm run db:migration -- --name …`.
  **Никогда** `prisma migrate reset` — сносит данные.
- Docker-образы локально не собирать (диск C), кеш сборки Docker не чистить без команды Евгения.

## Где что лежит

- Страницы — в базе (`content.pages`: блоки), правятся в админке (поля слева или щелчком по тексту
  прямо в предпросмотре) или через API контент-сервиса `/admin/v1/…` (заголовок X-Admin-Token из platform/.env).
- Практикум (`/praktikum/…`) — страницы-документы: целый HTML в `content.pages.body` (kind=document) — только
  статья и её стили; шапку, подвал, мобильное меню, общие стили и скрипты сайт ставит сам на места
  `<site-header></site-header>` и `<site-footer></site-footer>` (`apps/web/src/lib/site-chrome.tsx`), копии шапки
  в документ не вписывать. Правятся той же кнопкой «Изменить» (`DocumentEditor`): текст и картинки щелчком в
  предпросмотре (меняется ровно этот кусок исходника), вкладка «HTML-код», SEO — пишется в `<head>` документа.
  Документы без этих мест (рабочие листы для печати) отдаются как есть, панель администратора им — модуль `doc-bar`.
- Каталог — `content.categories / subcategories / products`: карточки и списки на сайте
  собираются из них. Админка: «Каталог продукции».
- Общие секции (преимущества, партнёры) — React-компоненты `packages/ui/src/blocks`, сверстаны один раз;
  под товарами — шаблоном категории. Их HTML в страницы не копировать.
- Оформление разделов страниц (показатели, заявка, этапы, «Почему выбирают»…) — одно на весь сайт:
  `apps/web/src/styles/sections.css` (после шаблонов и стилей страниц); в стили страниц и шаблоны не копировать.
- Формы обратной связи — компоненты `packages/ui/src/forms` (по одному на вид формы), все отправляют
  на `/api/send.php` (сервис заявок: база, раздел «Заявки» в админке, почта, Битрикс24). В HTML-секции
  форма ставится тегом `<ui-form type="request|short|express|call|catalog|spare" …>` — не копией разметки.
- Картинки и файлы — TimeWeb Cloud S3, Санкт-Петербург: бакеты `uralinduktor-assets` (файлы сайта) и
  `uralinduktor-private` (вложения заявок, удаляются через 30 дней), оба приватные — посетителям файлы отдаёт
  медиасервис. Админка «Медиатека», адреса `/img/…`, `/files/…`; оптимизация автоматическая —
  медиасервис: у каждой PNG/JPG сам делает WebP-копию (`foo.png.webp`: при загрузке, по первому запросу,
  при запуске — для старых) и отдаёт её по тому же адресу браузерам с WebP; уменьшенные копии `?w=` — в AVIF/WebP.
  Логотипы `apps/web/public/brand` — компонент `Logo` (`<picture>`), WebP-копии делает сборка сайта.
  Значок сайта (favicon) — рисунок `apps/web/public/favicon.svg`; ICO/PNG и логотипы админки из него и из
  brand/ — `npx tsx scripts/brand-icons.ts`. Исходники и архив — picture/.
- Стили сайта — `apps/web/public/css`. Скрипты — только TypeScript: модули `apps/web/src/client`,
  старые скрипты страниц `apps/web/src/legacy` (собираются в `public/js/<имя>.js` при `npm run build:web`,
  в git — только исходники .ts), служебные скрипты платформы — `platform/scripts/*.ts` (запуск через tsx).
- Анимации и поведение отдельных страниц — блок «Скрипт» (TypeScript/JS) в админке: контент-сервис
  при сохранении собирает его в файл `/js/page/<хеш>.js`, в HTML страницы `<script>` с кодом не пишем.
  У HTML-секции — свои вкладки «CSS» и «Скрипт» только для неё (`&` — сама секция, `section` — её
  элемент; метка `data-s`, логика — `packages/content-kit/src/section.ts`), на сайте — тоже файлами.
- Шапка, мобильное меню, подвал — React-компоненты `apps/web/src/components/layout` (`Header.tsx`, `Drawer.tsx`,
  `Footer.tsx`), одни на все страницы, включая Практикум. Пункты меню и подменю, мегаменю (иконки, подписи),
  контакты, подвал, оформление кнопок — данные: админка «Шапка, меню, контакты» (подпункт мобильного меню
  берёт иконку и подпись у пункта мегаменю с тем же адресом). Новый вид элемента — правка компонента; стили
  мобильного меню — `apps/web/public/css/mobile-fixes.css` (раздел 5). `design/prototypes/_partials` — прототипы
  эпохи Astro, сайтом не используются.
- Иконки SVG в блоках — окно «Иконка и цвет» (`apps/admin/src/components/icon-picker.tsx`), набор Solar —
  `apps/admin/public/icons/solar-linear.json` (`scripts/icons-solar.ts`); цвет — `style="color:…"` у `<svg>`
  (в HTML-секциях при сохранении остаётся на месте, в класс не уходит).
- Тёмная тема — `<html data-theme="dark">`: переключатель в шапке (`apps/web/src/client/theme.ts`), токены и свои
  правила — `apps/web/src/styles/theme-dark.css`. Цвета в CSS (сайт, шаблоны, стили страниц) получают тёмные значения
  сами (`packages/content-kit/src/dark.ts`: при сборке и при отдаче стилей страниц) — новый CSS пишется как обычно.
- Виджеты конструктора (текст, сетка фото, карусель, бегущая строка, видео, колонки, призыв, отступ) —
  блоки `packages/ui/src/blocks/Widgets.tsx`, стили `apps/web/src/styles/widgets.css`; добавляются в админке
  панелью «Добавить блок» (`apps/admin/src/components/widgets.tsx`) или «+» у блока в предпросмотре.
- Email-рассылки — админка «Email-рассылки» (базы: файлы Excel/CSV/TXT, заявки сайта, CRM; письмо HTML с
  предпросмотром; UTM-метки ставит система; статистика переходов — там и на «Обзоре»), сервис `services/mailing`
  (:4105, отправитель — `src/worker.ts`), схема `mailing` в базе; ссылки писем — `/r/…` (сайт передаёт сервису).
  Локально — тестовый режим, письма не уходят. Подробнее — docs/mailing.md.
- Панель администратора на сайте (вошли в админку — сверху «Редактировать страницу» и т. д.) —
  `apps/web/src/client/admin-bar.ts`, данные — `/admin/api/v1/site-bar`.
- 2FA админки — коды из приложения (TOTP): включает каждый сам в «Настройках входа» (`(panel)/security`), сброс
  чужой — администратор в «Пользователях»; коды и резервные коды — `apps/admin/src/lib/totp.ts`, QR-код —
  `lib/qr.ts`, проверка при входе — `lib/two-factor.ts`.
- Праздничные баннеры главной (расписание, баннеры, поздравления, эффекты) — админка «Праздники»; модель и даты —
  `packages/content-model/src/holidays.ts`, шапка — `packages/ui/src/blocks/HomeHero.tsx`, эффекты —
  `apps/web/src/client/holiday-fx.ts`, стили — `apps/web/src/styles/holiday.css`.

## Workflow (цикл — команды)

/task (следующая задача из PLAN.md) · /fix (точечная правка с проверкой) ·
/page (новая страница по типу T0x) · /imagegen (картинка по канону) ·
/product-image (товарные картинки: цех-канон, товар/категория) ·
/massedit (массовые правки скриптом) · /status (где мы). /ship — выкладка отключена.

- Одна сессия = одна задача. Закрыл — новая сессия.
- Параллельные сессии допустимы ТОЛЬКО по разным разделам/файлам. Коммиты адресные —
  `git add` конкретных файлов, никогда «всё разом». Общие файлы (PLAN.md, picture.md)
  править коротко в конце партии.
- После каждой проверенной задачи: git-коммит + отметка в PLAN.md. Не спрашивай — делай.
- Любая правка вёрстки заканчивается проверкой (platform/tools/checks): до правки
  `npm run checks -- --save [--visual]`, после — `npm run checks [--visual]`, снимки отличий —
  глазами. Поведение сайта — `npx tsx tools/checks/src/functional-check.ts --no-submit`,
  админка — `tools/checks/src/admin-smoke.ts`.
- Запутался или поправили дважды — предложи /clear и новую сессию.

## Железные правила

1. URL: со слешем на конце, без .html, иерархия = хлебным крошкам. Смену адреса страницы
   каталога сопровождает 301 со старого (каталог делает сам).
2. Формы и общие секции — только компонентами (packages/ui), не HTML-копиями; в HTML — тег `<ui-form>`.
3. Картинки — в медиатеку по picture.md; генерация по канону style.md.
4. Новая страница — сначала тип (docs/page-types/), адрес и место в structura.md.
5. Выкладки нет — только локально (см. «Что это»).
6. Секреты (platform/.env, ключи, пароли) — не коммитить, не вписывать в доки. **Репозиторий на GitHub
   публичный** (github.com/IlyaCodex/mtpk-site): сведения о серверах (IP, вход, защита, выкладка) — только
   в локальных документах (в `.gitignore`), медиа (picture/, brand/, картинки вне platform/) — не в git.
7. Товарные картинки (перерисовать/заменить/добавить) — ТОЛЬКО через скил
   /product-image, даже если просьба сформулирована свободным текстом.
   Без скила не генерировать. Канон и промт — briefs/product-image-prompt.md.

server/          # конфиги старого боевого сервера — справочно
