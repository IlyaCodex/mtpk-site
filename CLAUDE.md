# Сайт МТПК / Уралиндуктор — корневой контекст

> Карта проекта, не свалка деталей. Детали — по навигации ниже.

## Что это

Сайт uralinduktor.ru на собственной платформе `platform/`: сайт и админка на Next.js,
сервисы (контент, медиа, заявки, поиск), данные в PostgreSQL (Prisma), кеш Redis,
файлы в S3 (локально MinIO). ~1000 адресов: страницы, каталог (категории →
подкатегории → товары), запчасти, Практикум. Подробнее о проекте: docs/project-info.md.

**Работаем только локально** (решение Евгения от 07.10.2026): выкладки нет, до полной
отладки ничего не выкладываем. Старый сайт на Astro удалён из репозитория (остался в
истории git); на боевом домене пока работает он.

## Главное правило

Ищи простое решение. Не выдумывай ничего, что уже описано в документах:
стиль — style.md, структура — structura.md, типы страниц — docs/page-types/.
Не хватает информации — спроси Евгения, не фантазируй.

## Стек и локальный запуск (из `platform/`)

- Инфраструктура: `npm run infra:up` — Postgres (:5442), Redis, MinIO в Docker Desktop.
- Сервисы: `npm run dev` — контент :4101, заявки :4102, поиск :4103, медиа :4104.
- Сайт: `npm run build:web` → `npm run start -w @mtpk/web` — http://127.0.0.1:3200.
- Админка: `npm run dev -w @mtpk/admin` — адрес `/admin`: http://127.0.0.1:3300/admin, через сайт —
  http://127.0.0.1:3200/admin (на домене — uralinduktor.ru/admin). Вход — только по секретной ссылке
  `/admin/login?token=<ADMIN_LOGIN_TOKEN из platform/.env>`, без неё админка отвечает 404.
  Токен не публиковать; новый токен в .env отменяет выданные пропуска.
- База: схема и миграции — packages/db/prisma; новая миграция — `npm run db:migration -- --name …`.
  **Никогда** `prisma migrate reset` — сносит данные.
- Docker-образы локально не собирать (диск C), кеш сборки Docker не чистить без команды Евгения.

## Где что лежит

- Страницы — в базе (`content.pages`: блоки), правятся в админке или через API
  контент-сервиса `/admin/v1/…` (заголовок X-Admin-Token из platform/.env).
- Каталог — `content.categories / subcategories / products`: карточки и списки на сайте
  собираются из них. Админка: «Каталог продукции».
- Общие секции (формы заявки, преимущества, партнёры) — React-компоненты
  `packages/ui/src/blocks`, сверстаны один раз; под товарами — шаблоном категории.
  Их HTML в страницы не копировать.
- Картинки и файлы — S3 (админка «Медиатека»), адреса `/img/…`, `/files/…`;
  уменьшенные копии и WebP/AVIF делает медиасервис. Исходники и архив — picture/.
- Стили сайта — `apps/web/public/css`. Скрипты — только TypeScript: модули `apps/web/src/client`,
  старые скрипты страниц `apps/web/src/legacy` (собираются в `public/js/<имя>.js` при `npm run build:web`,
  в git — только исходники .ts), служебные скрипты платформы — `platform/scripts/*.ts` (запуск через tsx).
- Анимации и поведение отдельных страниц — блок «Скрипт» (TypeScript/JS) в админке: контент-сервис
  при сохранении собирает его в файл `/js/page/<хеш>.js`, в HTML страницы `<script>` с кодом не пишем.
- Шапка, меню, контакты, подвал — админка «Шапка, меню, контакты».

## Workflow (цикл — команды)

/task (следующая задача из PLAN.md) · /fix (точечная правка с проверкой) ·
/page (новая страница по типу T0x) · /imagegen (картинка по канону) ·
/product-image (товарные картинки: цех-канон, товар/категория) ·
/massedit (массовые правки скриптом) · /status (где мы). /ship — выкладка отключена.

- Одна сессия = одна задача. Закрыл — новая сессия.
- Параллельные сессии допустимы ТОЛЬКО по разным разделам/файлам. Коммиты адресные —
  `git add` конкретных файлов, никогда «всё разом». Общие файлы (PLAN.md, picture.md)
  править коротко в конце партии.
- После каждой проверенной задачи: git-коммит + отметка в PLAN.md. Не спрашивай — делай.
- Любая правка вёрстки заканчивается проверкой (platform/tools/checks): до правки
  `npm run checks -- --save [--visual]`, после — `npm run checks [--visual]`, снимки отличий —
  глазами. Поведение сайта — `npx tsx tools/checks/src/functional-check.ts --no-submit`,
  админка — `tools/checks/src/admin-smoke.ts`.
- Запутался или поправили дважды — предложи /clear и новую сессию.

## Железные правила

1. URL: со слешем на конце, без .html, иерархия = хлебным крошкам. Смену адреса страницы
   каталога сопровождает 301 со старого (каталог делает сам).
2. Формы и общие секции — только компонентами (packages/ui), не HTML-копиями.
3. Картинки — в медиатеку по picture.md; генерация по канону style.md.
4. Новая страница — сначала тип (docs/page-types/), адрес и место в structura.md.
5. Выкладки нет — только локально (см. «Что это»).
6. Секреты (platform/.env, ключи, пароли) — не коммитить, не вписывать в доки.
7. Товарные картинки (перерисовать/заменить/добавить) — ТОЛЬКО через скил
   /product-image, даже если просьба сформулирована свободным текстом.
   Без скила не генерировать. Канон и промт — briefs/product-image-prompt.md.
