# Сайт МТПК / Уралиндуктор — корневой контекст

> Карта проекта, не свалка деталей. Детали — по навигации ниже.

## Что это

Боевой сайт https://uralinduktor.ru/ — новая статика на Astro взамен старого
WordPress. Домен уже переключён на Astro-сборку (2026-06, веха «Домен» закрыта);
поддомен https://new.uralinduktor.ru/ остался как 301-редирект на основной домен.
~406 URL. Подробнее: docs/project-info.md.

## Главное правило

Ищи простое решение. Не выдумывай ничего, что уже описано в документах:
стиль — style.md, структура — structura.md, типы страниц — docs/page-types/.
Не хватает информации — спроси Евгения, не фантазируй.

## Стек

Astro (SSG) + Tailwind · raw-pages для контентных страниц · формы → send.php
(Битрикс24+email) · Pagefind · прод: VPS `uralinduktor-prod`,
`/var/www/uralinduktor-astro/`, деплой rsync. Репозиторий: локальный git (с 2026-06-04).

## Где живёт состояние проекта

- **PLAN.md** — бэклог доработок + трекер (Сейчас → Бэклог → веха «Домен»). ЕДИНСТВЕННЫЙ источник «что сделано/что дальше». История строительства (этапы 1–14) — docs/plan-archive.md.
- **structura.md** — дерево URL и статусы страниц.
- **picture.md** — карта картинок. **style.md** — дизайн-система.
- Состояние НЕ дублировать в этом файле — протухает.

## Workflow (цикл — команды)

/task (следующая задача из PLAN.md) · /fix (точечная правка с проверкой) ·
/page (новая страница по типу T0x) · /imagegen (картинка по канону) ·
/product-image (товарные картинки: цех-канон, товар/категория) ·
/massedit (массовые правки скриптом) · /ship (деплой) · /status (где мы).

- Одна сессия = одна задача. Закрыл — новая сессия.
- Параллельные сессии допустимы ТОЛЬКО по разным разделам/файлам. Правила:
  (1) коммиты адресные — `git add` конкретных файлов, никогда «всё разом»;
  (2) /ship делает одна сессия за раз и только когда `git status` не показывает
  чужих незакоммиченных правок в страницах/картинках — иначе спроси Евгения;
  (3) общие файлы (PLAN.md, picture.md) править коротко в конце партии.
- После каждой проверенной задачи: git-коммит + отметка в PLAN.md. Не спрашивай — делай.
- Любая правка верстки заканчивается скриншот-проверкой (см. скилы).
- Деплой — только по явной команде (/ship).
- Запутался или поправили дважды — предложи /clear и новую сессию.

## Железные правила (детали — в доках)

1. URL: pretty URLs без .html, иерархия = хлебным крошкам → docs/conventions.md
2. Пути к ассетам — только абсолютные с `/` → docs/conventions.md
3. Шапка/футер — только через партиалы + sync-partials.py → docs/conventions.md
4. Формы — всегда `js-lead-form` + honeypot + hidden-поля, копировать из рабочей → docs/forms.md
5. Картинки — в picture/ по picture.md; генерация по канону style.md
6. Новая страница — сначала тип (docs/page-types/), URL и место в structura.md → docs/conventions.md
7. Деплой — только по docs/deploy-gotchas.md (симлинк img!, _astro/, права 644)
8. Секреты (send.php конфиг, ssh-ключи) — не коммитить, не вписывать в доки.
9. Товарные картинки (перерисовать/заменить/добавить) — ТОЛЬКО через скил
   /product-image, даже если просьба сформулирована свободным текстом.
   Без скила не генерировать. Канон и промт — briefs/product-image-prompt.md.
