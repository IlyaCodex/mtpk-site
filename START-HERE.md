# С чего начать — ведение сайта new.uralinduktor.ru

> Это рабочая копия проекта сайта для передачи новому ответственному.
> Прочитай этот файл целиком — здесь всё, что нужно, чтобы начать вносить
> правки и публиковать их. Личных доступов (SSH-ключ, пароли) в архиве нет —
> их ты заводишь сам (см. раздел 2).

---

## 1. Что это за сайт (за 1 минуту)

- Сайт **статический**: это набор готовых HTML-файлов. Нет базы данных,
  нет админки, нет «движка».
- Собирается генератором **Astro** из исходников (папка `astro/`).
  Контент — текстовые файлы (`.md`, `.html`), один файл = одна единица.
- Любая правка проходит один и тот же цикл:

  ```
  правишь файл  →  npm run build (пересборка)  →  заливка на сервер (деплой)
  ```

- Формы заявок обрабатывает один PHP-скрипт `send.php` на сервере
  (его исходник — в `server/api/send.php`).

**Источник правды — эта папка.** Сервер хранит только производную копию
(собранный сайт). Поэтому правим всегда здесь, у себя, потом публикуем.

## 2. Что нужно завести самому (один раз)

В архиве сознательно **нет личных доступов и секретов**. Их получи у Евгения
и заведи у себя:

1. **Node.js** (LTS-версия) — чтобы работала сборка. Поставь с nodejs.org.
2. **SSH-доступ к серверу.** Тебе передадут отдельно: IP/адрес сервера и
   приватный SSH-ключ. Пропиши алиас в `~/.ssh/config`, чтобы команда
   `ssh uralinduktor-prod` подключалась сразу (как это сделать — см.
   `briefs/hosting-spec.md`, раздел про SSH).
3. **Секреты формы** (только если будешь трогать заявки): SMTP-пароль,
   вебхук Битрикс24 и т.п. живут в файле `secrets.php` **на сервере**, вне
   проекта. Шаблон и инструкция — `briefs/tz-form-secrets-smtp.md`.
   В этот проект секреты НЕ вписываются никогда.

Установка зависимостей проекта (один раз после распаковки):

```bash
cd astro
npm install
```

## 3. Три способа управлять сайтом

Сайт и процесс под ними **одинаковые**. Разница только в том, кто пишет
команды и правит файлы. Выбирай по ситуации.

### Способ A — через Claude Code (основной, проще всего)

Проект заточен под Claude Code: в нём лежат готовые команды-скилы.
Ставишь Claude Code, открываешь эту папку — и работаешь обычным языком.
Ключевые команды:

| Команда | Что делает |
|---|---|
| `/status` | Где мы сейчас, что в работе |
| `/fix`    | Точечная правка страницы с авто-проверкой вёрстки (скриншот до/после) |
| `/task`   | Взять следующую задачу из `PLAN.md` |
| `/page`   | Новая страница по типу |
| `/ship`   | **Деплой на прод по чек-листу** (сам собирает, заливает, проверяет) |

`/ship` — самый ценный: он знает «грабли» сервера (не снести симлинк
картинок, залить CSS вместе со страницей) и проверяет сайт после заливки.
Деплой руками без него — рискованнее (см. способ C).

### Способ B — через GPT / ChatGPT (запасной консультант)

GPT не знает про скилы `/ship` и `/fix` — это фишка Claude. Но он помогает
как умный подсказчик: скармливаешь ему `MAINTENANCE.md` + нужный файл, и он
объясняет, что поправить, генерирует команды, разбирает ошибки. Сами команды
(`npm run build`, заливку) запускаешь в терминале руками. Хорош для «объясни,
что значит эта ошибка».

### Способ C — руками, без AI (через Astro)

Ты фронтендер — это тебе доступно. Открываешь нужный файл в редакторе,
правишь, потом три команды:

```bash
cd astro
npm run build                              # пересобрать (сам соберёт и поиск)
# залить на сервер (ВНИМАТЕЛЬНО — см. ниже про --exclude=img):
rsync -az --delete --exclude=img dist/ uralinduktor-prod:/var/www/uralinduktor-astro/
ssh uralinduktor-prod 'chown -R www-data:www-data /var/www/uralinduktor-astro'
```

> ⚠️ **Боевой каталог на сервере — `/var/www/uralinduktor-astro/`**
> (не `/var/www/uralinduktor/public/` — это старый каталог).
> ⚠️ **`--exclude=img` обязателен:** на сервере `img` — это симлинк на хранилище
> картинок. Без exclude `--delete` снесёт его, и ВСЕ картинки отдадут 404.
> Полная процедура и все «грабли» — `docs/deploy-gotchas.md` +
> `briefs/hosting-spec.md`. **Прочитай их перед первым деплоем руками.**

Проверка после деплоя:
```bash
curl -I https://new.uralinduktor.ru/      # ожидаем 200 OK
```

## 4. Что НЕ входит в этот архив (и когда понадобится)

Чтобы архив был лёгким, в него не положены тяжёлые материалы этапа
*постройки* сайта (они не нужны для повседневного ведения):

- `site/` — слепок старого сайта (источник для миграции).
- `design/` — 269 HTML-прототипов (этап дизайна закрыт; оставлены только
  служебные `prototypes/build/` и `_partials/`, чтобы `/ship` работал).
- `_astro_assets/`, `generated/`, `content-source/` — рабочие материалы миграции.
- `node_modules/`, `dist/` — регенерируются (`npm install`, `npm run build`).
- `ФОТО/` — сырые фото (7.8 ГБ, бэкапятся отдельно).

Если понадобится перерисовать товарную картинку «из исходников старого сайта»
(скил `/product-image`) или поднять прототипы — запроси полную версию проекта
у Евгения.

## 6. Золотые правила (короткий список)

1. Правим всегда **здесь, у себя**, никогда не редактируем файлы прямо на
   сервере — они перезапишутся при следующем деплое.
2. Деплой руками — только прочитав `docs/deploy-gotchas.md` (симлинк `img`!,
   правильный каталог `-astro`, права 644).
3. Секреты (SSH-ключ, пароли формы) — **не вписывать в проект и не слать в
   чат AI**. Они живут вне проекта.
4. Запутался — в Claude Code набери `/status` или спроси Евгения. Не фантазируй.
