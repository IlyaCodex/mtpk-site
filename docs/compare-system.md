# Подсистема «Сравнение товаров»

> **С 07.10.2026 сайт — платформа `platform/`** (Next.js, база, админка), папка `astro/` удалена. Пути вида
> `astro/src/raw-pages/…` и `astro/public/…` в тексте ниже — исторические: страницы теперь в базе (админка),
> картинки — в медиатеке (S3), адреса `/img/…` те же. Актуальное устройство — [`CLAUDE.md`](../CLAUDE.md).

Как устроена кнопка «К сравнению», страница `/sravnenie/` и передача
выбранных позиций менеджеру.

*Создан: 2026-09-23. Обновляй при изменении архитектуры.*

---

## 1. Что видит посетитель

1. В карточках каталога и на странице товара — кнопка **«К сравнению»**
   (активная: «В сравнении»).
2. Внизу экрана — панель со счётчиком и кнопкой «Сравнить». Она висит на
   любой странице, пока в сравнении что-то есть, и не показывается на самой
   странице сравнения.
3. `/sravnenie/` — таблица: слева параметры (колонка липкая), дальше по
   колонке на модель. Переключатель «показать только отличия», удаление
   позиции крестиком, «очистить сравнение».
4. Под таблицей — форма заявки с кнопкой **«Отправить менеджеру на просчёт»**.

Ограничения: **4 позиции**, только **внутри одного раздела**. При попытке
добавить товар из другого раздела спрашиваем, начинать ли новое сравнение.

## 2. Откуда берутся характеристики

Из таблиц блока «Характеристики и описание» на страницах товара (`section.cdoc`,
разбор — `platform/packages/content-kit/src/compare.ts`) — то есть из того же места,
которое видит посетитель. Отдельного конфига нет специально: второй список
характеристик неизбежно разошёлся бы с первым.

`astro/scripts/build-compare-index.mjs` (запускается в `prebuild`, то есть
при каждой сборке) пишет два файла:

| Файл | Размер | Кто грузит |
|---|---|---|
| `public/data/compare-index.json` | ~420 КБ | только `/sravnenie/` |
| `public/data/compare-sections.json` | ~1,5 КБ | все страницы каталога |

Второй — просто список адресов разделов, где сравнение включено: по нему
`compare.js` решает, ставить ли кнопку, не таща на каждую страницу
весь индекс.

## 3. Какие разделы попадают в сравнение

Скрипт решает сам, по сопоставимости характеристик:

- в разделе **≥ 3 моделей**;
- **≥ 5 параметров** встречаются хотя бы у половины моделей раздела.

Сейчас проходят 26 разделов и 251 позиция: печи, дробемёты, чиллеры,
градирни, ковши, нагреватели.

Не проходят проектные комплексы — ЛВМ, ЛГМ, ХТС и подобные: там каждая
позиция описана по-своему (в ЛВМ на 21 страницу приходится 100 разных
названий строк), и таблица сравнения была бы пустой сеткой.

Посмотреть решение по разделам: `npm run compare` — печатает, что включено
и что отсеяно, с числом общих строк.

Если название одного и того же параметра на страницах пишут по-разному —
добавь пару в `SYNONYMS` в начале скрипта. Принудительно выключить раздел
можно через `DENY`.

## 4. Хранение выбора

`localStorage`, ключ `ui_compare`:

```json
{ "section": "/products/.../kranovogo-tipa/", "items": ["/products/.../uid-376/"], "ts": 1790000000000 }
```

Живёт 30 дней. Все обращения обёрнуты в try/catch: в приватном режиме
хранилище может быть недоступно — тогда кнопка просто не запоминает выбор,
страница при этом не ломается.

Не путать с `sessionStorage.ui_quote_items` — это соседний механизм кнопки
«Запросить цену» (`quote-form.js`), он живёт отдельно.

## 5. Что уходит менеджеру

Отдельного поля формы нет намеренно: `/api/send.php` читает фиксированный
набор полей (`name`, `phone`, `email`, `task`, `source`, …) и незнакомые
молча отбрасывает. Поэтому список позиций дописывается в **`task`**:

```
Сравнение (3 поз.), раздел «Для стали и чугуна»:
1. УИ-0.1Т-100 — uralinduktor.ru/products/.../ui-0-1t-100/
2. УИ-0.15Т-160 — uralinduktor.ru/products/.../ui-0-15t-160/
3. УИ-0.25Т-160 — uralinduktor.ru/products/.../ui-0-25t-160/
Отличия по: Номинальная масса одной плавки · Номинальная мощность ТПЧ
```

Ручной текст клиента сохраняется ниже этого блока. В Битрикс24 заявка
приходит с меткой источника `data-form="Сравнение товаров"`.

Если однажды понадобится отдельное поле в карточке лида — это правка
боевого `send.php` (он вне репозитория, `/var/www/uralinduktor/api/`).

## 6. Файлы

```
astro/scripts/build-compare-index.mjs   сборка индекса (prebuild)
astro/public/js/compare.js              кнопки, панель, хранилище (все страницы)
astro/public/js/compare-page.js         таблица и форма на /sravnenie/
astro/public/css/site.css               стили кнопки и панели (глобальные)
astro/src/raw-pages/sravnenie/          сама страница + её стили
```

Страница служебная: `noindex` через `meta.json`, вне sitemap
(`astro.config.mjs`) и вне поиска Pagefind (`isUtility` в `[...slug].astro`).

## 7. Грабли

- **Порядок скриптов.** `compare-page.js` стоит в разметке страницы, а
  `compare.js` — в общем блоке скриптов, то есть ниже. Поэтому страница
  ждёт `DOMContentLoaded`, к которому отработали оба defer-скрипта.
- **Кнопки не в разметке.** В карточках их рисует скрипт: карточек 233 и
  все одинаковые, руками такое не поддерживается.
- **Нулевой ширины пробелы.** В значениях вроде `м³/⁠ч` стоит word joiner:
  при разборе его надо выкидывать, а не заменять пробелом, иначе в таблице
  появляется «м³/ ч».
