# Подсистема «Email-рассылки»

Как устроены рассылки по базам адресов: откуда берутся адреса, как собирается
письмо, кто ставит UTM-метки, как считаются переходы и что нужно для настоящей
отправки.

*Создан: 2026-10-13. Обновляй при изменении архитектуры.*

---

## 1. Где что

| Что | Где |
|---|---|
| Раздел админки | «Продажи → Email-рассылки» (`apps/admin/src/app/(panel)/mailing/`), права — admin и manager |
| Сервис | `services/mailing` (:4105): API для админки `/admin/v1/…`, ссылки из писем `/r/…` |
| Отправитель | `services/mailing/src/worker.ts` (процесс `mailing-worker`) |
| Данные | схема `mailing` в базе: contacts, lists, list_members, campaigns, recipients, links, clicks, imports |
| Фирменный шаблон письма | `services/mailing/src/template.ts` (кнопка «Фирменный шаблон» в редакторе) |
| На «Обзоре» админки | переходы из писем за 30 дней и последние рассылки |

Локально `npm run dev` запускает сервис и отправителя вместе с остальными сервисами.

## 2. Базы адресов

База — список адресов, по которому уходит рассылка. Контакт (адрес) один на всю
систему и может быть в нескольких базах; повторы не задваиваются, имя, компания
и телефон дополняются, но не затираются.

Пополнение базы:

- **Файл** `.xlsx`, `.xls` (выгрузка Битрикс24 — HTML-таблица; старый двоичный .xls — только адреса),
  `.csv`, `.txt` до 25 МБ. Кодировка UTF-8 или Windows-1251 (1С) определяется сама. Колонки
  «E-mail / Имя / Компания / Телефон» ищутся по заголовкам, без заголовков адреса берутся из
  любых ячеек. Сначала проверка (что нашлось, повторы, ошибки, первые 10 строк), потом загрузка.
- **Списком** — адрес на строку или через запятую, «Имя <адрес>», «Имя; адрес».
- **Из заявок сайта** за период (таблица `leads.leads`, у кого указан e-mail).
- **Из CRM Битрикс24** — контакты, компании, лиды с e-mail, в фоне (по 50 записей, пауза 0,5 с:
  15 000 адресов — 5–10 минут). Нужен входящий вебхук `B24_WEBHOOK` с правом «CRM» (тот же, что
  у сервиса заявок).

Статусы контакта: `active` — получает письма; `unsubscribed` — отписался (по ссылке или вручную
в «Все адреса и отписки»); `bounced` — почтовый сервер ответил, что адреса нет. Отписка действует
на все базы и сохраняется, даже если адрес загрузят снова.

## 3. Письмо

- HTML в редакторе кода: таблицы шириной до 600 px, стили в `style` — почтовые программы не
  понимают внешние стили и скрипты. Картинки — из медиатеки, по https.
- Подстановки: `{{name|коллеги}}` (имя или запасное слово), `{{email}}`, `{{site_url}}`,
  `{{unsubscribe_url}}` — **обязательна**, без неё рассылку не запустить.
- Предпросмотр — как во «Входящих» (отправитель, тема, прехедер) и само письмо на компьютере и
  телефоне; замечания: нет темы или отписки, письмо тяжелее 100 КБ (Gmail обрежет), картинки по
  http, `<script>`, нет метки. Внизу — все ссылки с итоговыми адресами и текстовая версия.
- Тестовое письмо — до 5 адресов, тема с «[Тест]», ссылки сразу на адреса с метками (не считаются).
- После запуска письмо не меняется; повтор — «Копия».

## 4. UTM-метки и переходы

При запуске каждая ссылка письма на свой сайт (`MAILING_OWN_HOSTS` + адрес сайта) получает метки:

```
utm_source=email  utm_medium=email
utm_campaign=<метка рассылки>   — из названия: 2026-10-novinki-oktyabrya (можно поменять)
utm_content=<текст ссылки>      — транслитом; повтор — с номером; своё — атрибут data-utm="…"
```

Свои метки в ссылке не перезаписываются; ссылки на чужие сайты — без меток. `data-notrack` у
ссылки — не отслеживать. Почта, телефон и отписка не отслеживаются.

В отправленном письме ссылка ведёт на сайт: `/r/c/<ссылка>/<токен получателя>` — переход
записывается и сразу переадресует (302) на адрес с метками. Открытие — картинка
`/r/o/<токен>.gif`. Не считаются: роботы (антиспам почты, превью мессенджеров) и ссылки с чужим
или испорченным токеном — их всё равно переадресует. Сайт передаёт `/r/` сервису (`next.config.ts`,
на сервере — шлюз `infra/gateway/nginx.conf`).

Отписка: `/r/u/<токен>` — страница с кнопкой (проверяльщики ссылок не отписывают сами), POST —
отписать; в письме — заголовки `List-Unsubscribe` и `List-Unsubscribe-Post` (отписка в один клик
из почтовой программы, RFC 8058).

## 5. Отправка

- Запуск сейчас или по расписанию. Отправитель готовит получателей — активные адреса базы на
  момент запуска — и ссылки, затем шлёт пачками.
- Очередь — в базе (`recipients`): пачки берутся с блокировкой строк (`FOR UPDATE SKIP LOCKED`),
  одно письмо не уйдёт дважды. Темп — `MAILING_RATE` писем в секунду (5 — это 15 000 писем за
  ≈ 50 минут). Временная ошибка — до 3 попыток; «адреса нет» — контакт `bounced`.
- Пауза и «Остановить» действуют между пачками; отписавшиеся после запуска пропускаются.
- Удалить можно черновик и рассылку без отправленных писем (у отправленных — статистика).

## 6. Режимы и настройка сервера

| Переменная | Что |
|---|---|
| `MAILING_TRANSPORT` | `log` — тестовый режим: всё как при отправке, но письма не уходят (локально); `smtp` — отправка |
| `MAILING_SMTP_HOST/PORT/SECURE/USER/PASS` | почтовый сервис для рассылок |
| `MAILING_FROM`, `MAILING_REPLY_TO` | адрес отправителя и для ответов (имя отправителя — в рассылке) |
| `MAILING_RATE` | писем в секунду — по лимиту почтового сервиса |
| `MAILING_PUBLIC_URL` | адрес сайта в письмах; пусто — `SITE_URL` (при разработке — `WEB_URL`) |
| `B24_WEBHOOK` | вебхук Битрикс24 — загрузка адресов из CRM |

Перед настоящей рассылкой:

1. Почтовый сервис для массовых писем (Unisender Go, Yandex 360, Mail.ru для бизнеса и т. п.),
   а не обычный ящик: у обычных лимит в сотни писем в сутки.
2. У домена отправителя — записи SPF, DKIM и DMARC, иначе письма уйдут в спам.
3. Первые рассылки — небольшими объёмами (прогрев домена), темп — по лимиту сервиса.
4. Рекламные письма — только тем, кто давал согласие (ст. 18 закона «О рекламе»); отписка в
   каждом письме обязательна. Адреса — персональные данные (152-ФЗ).
