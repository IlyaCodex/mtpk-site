# Цикл работы с ТЗ-правками (PDF от Евгения)

> ТЗ = PDF с правками формата «ссылка / скрин / описание» (пример: тз1.pdf
> в корне). Этот README — процедура для сессий. Евгению достаточно двух команд.

## Цикл для Евгения (коротко)

1. Положи PDF в корень проекта (тз2.pdf, тз3.pdf…).
2. Новая сессия: **«разбери тз2.pdf по docs/edits/README.md»** → сессия делает
   триаж-чеклист docs/edits/tz2.md + строку в PLAN.md «Сейчас» + задаёт ВСЕ
   вопросы по неясным пунктам сразу, одним списком.
3. Дальше обычный цикл: **/task** в новых сессиях — правки выполняются по
   чеклисту до закрытия ТЗ.
4. ТЗ закрыто → **/ship** одной пачкой → смоук → проверяешь правки на проде
   по списку.

## Триаж (сессия-разборщик)

Каждый пункт ТЗ → строка чеклиста в docs/edits/tzN.md в формате:

```
- [ ] **N. <суть>** · <URL> · инструмент: /fix | /massedit | /imagegen |
      /product-image | структурная · размер: S/M/L · <детали, пути к файлам>
```

Правила триажа:
- Размеры: S — точечная правка (текст, имя, картинка по готовому канону);
  M — страница/раздел или массовая замена; L — структурное (URL, меню,
  перестройка раздела).
- Порядок строк = порядок выполнения: сначала S (быстрые победы), потом M,
  L — последними, каждая L — строго отдельной сессией.
- Неясности НЕ угадывать: пометить `❓` в пункте и задать Евгению все вопросы
  по ТЗ сразу при триаже, одним списком.
- В PLAN.md «Сейчас» добавить строку: `ТЗ-N: правки 0/<кол-во> → docs/edits/tzN.md`.

## Выполнение (рабочие сессии, /task)

- /task видит строку ТЗ в PLAN.md → открывает чеклист → берёт ПЕРВЫЙ незакрытый
  пункт.
- S-пункты можно делать подряд несколько за сессию; M — 1–2 за сессию;
  L — одна на сессию. Запутался — /clear, следующая сессия продолжит с
  первого незакрытого.
- Каждая правка: выполнение → скриншот-проверка (shot.sh, до/после для
  верстки) → git-коммит `тзN-<номер>: <суть>` → отметка [x] в чеклисте
  (+ счётчик в PLAN.md) — всё ОДНИМ заходом, не копить.
- Картинки — только через /product-image (товарные) и /imagegen (hero) —
  правило #9 CLAUDE.md. Массовые текстовые замены — /massedit.
- Последний пункт закрыт → в чеклист дописать блок «Итог: что сделано,
  что пропущено/вопросы» и сказать Евгению, что ТЗ готово к /ship.

## Деплой

- НЕ деплоить по одной правке. ТЗ закрыто целиком → /ship одной пачкой →
  смоук (docs/deploy-gotchas.md §5-6) → Евгений проверяет на проде.
- ⚠️ Пока открыт пункт «синхронизация репо↔прод» в PLAN.md — /ship запрещён,
  правки копятся локально в коммитах. Сначала синхронизация.
