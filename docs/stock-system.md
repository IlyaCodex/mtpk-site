# Подсистема «Наличие на складе»

Этот документ описывает, как устроен раздел `/nalichie/` и как им управлять.
Связан со страницей `/nalichie/` и с **бейджами «В наличии»** на карточках
товара в каталоге `/products/...`.

*Создан: 2026-05-30. Обновляй при изменении архитектуры.*

---

## 1. Что делает система

Один файл-конфиг (`astro/data/stock.config.json`) — два эффекта на сайте:

1. **`/nalichie/` → секция «Сейчас на складе»** — карточки `.pcard` со
   ссылкой на товар, зелёным бейджем «В наличии» и фильтром по категориям.
2. **`/products/.../` → бейдж «В наличии»** — зелёная плашка слева-сверху на
   обложке карточки товара (в каталогах подкатегорий). Клик по бейджу ведёт
   на `/nalichie/`.

Источник правды — один. Названия, фото, категорию **не нужно вписывать руками**
— скрипт сам забирает их со страницы товара (из `raw-pages/.../body.html`
+ `meta.json`).

---

## 2. Как добавить позицию

1. Открой `astro/data/stock.config.json`.
2. Добавь объект в массив `items`:
   ```json
   { "url": "/products/induktsionnoe-oborudovanie/.../модель/" }
   ```
3. Опциональные поля:
   - `qty` *(число)* — сколько штук на складе, выведется как «N шт» под
     названием карточки.
   - `shipping` *(строка)* — текст отгрузки, например `"от 1 рабочего дня"`.
   - `note` *(строка)* — заметка для оператора (на страницу не выводится,
     просто полезно при просмотре конфига).
4. Пересобрать и задеплоить:
   ```bash
   cd astro
   npm run stock     # резолвер вытаскивает мета (можно для проверки)
   npm run build     # автоматически прогоняет stock через prebuild
   # деплой как обычно — см. CLAUDE.md и MAINTENANCE.md
   ```

### Пример «полного» item
```json
{
  "url": "/products/induktsionnye-plavilnye-pechi/po-stali/ui-0-25t-250/",
  "qty": 1,
  "shipping": "от 1 рабочего дня"
}
```

### Что НЕ нужно писать руками
| Поле | Откуда автоматически берётся |
|---|---|
| `title` | `<h1 class="phero__title">` со страницы товара (или `meta.title`) |
| `category` | Имя первой ссылки в breadcrumb (`/products/<cat>/`) |
| `image` | `<img class="phero__main">` или `phero__hero` или первое `<img>` |
| `slug` | URL без `/products/` и trailing slash (нужен для бейджей в каталоге) |

---

## 3. Как убрать позицию

Удали соответствующий объект из массива `items` в `stock.config.json` →
пересборка → товар исчезает и из `/nalichie/`, и бейдж снимается в каталоге.

---

## 4. Сухой прогон без полной сборки

```bash
cd astro
npm run stock        # читает config, резолвит мета, пишет public/data/stock.json
                     # --verbose: видит каждую успешно зарезолвенную позицию
```

Если URL некорректный или товара нет в `raw-pages/`, скрипт выведет
предупреждение `[stock] ⚠ не нашёл src/raw-pages/...` и пропустит запись.

---

## 5. Архитектура

```
astro/data/stock.config.json          ← ИСТОЧНИК ПРАВДЫ. Правишь только этот файл.
       │                              ─── только URL'ы + опц. qty/shipping/note
       │
       ▼  npm run stock (=> prebuild)
       │  scripts/build-stock.mjs парсит raw-pages/<url>/{body.html, meta.json}
       │  и обогащает каждый item: title, category, image, slug
       │
astro/public/data/stock.json          ← АВТОГЕН. Не редактировать вручную.
       │
       ▼  при загрузке страницы — fetch
       │
/data/stock.json
       │
       ├──►  /js/stock-list.js     →  карточки + фильтр на /nalichie/
       │     (рендер на клиенте,
       │      контейнер [data-stock-grid])
       │
       └──►  /js/stock-badges.js   →  бейдж «В наличии» в каталогах
             (вешает .pcard__stock-badge      /products/.../<cat>/
              на карточки с совпавшим slug)
```

### Файлы

| Путь | Назначение |
|---|---|
| `astro/data/stock.config.json` | **Ист. правды.** Редактирует оператор/тимлид. |
| `astro/scripts/build-stock.mjs` | Резолвер. Запускается через `npm run stock` или автоматически как `prebuild`. |
| `astro/public/data/stock.json` | Автоген. Обогащённый файл для рантайма. **Не коммитить руками.** |
| `astro/public/js/stock-list.js` | Клиентский рендер карточек + фильтра на `/nalichie/`. |
| `astro/public/js/stock-badges.js` | Клиентский навешиватель бейджа на карточки каталога. |
| `astro/public/css/stock.css` | Глобальные стили: бейдж, мета-поля карточки, обёртка фильтра. Подключён в `BaseLayout.astro`. |
| `astro/src/raw-pages/nalichie/body.html` | Сама страница `/nalichie/`. |

### npm-скрипты

```json
"scripts": {
  "stock":    "node scripts/build-stock.mjs --verbose",
  "prebuild": "node scripts/build-stock.mjs",
  "build":    "astro build",
  ...
}
```

`prebuild` выполняется автоматически перед каждым `npm run build` — стоит
**не отключать**, иначе `public/data/stock.json` уйдёт на прод устаревшим.

---

## 6. Фильтр по категориям

Фильтр **полностью динамический**: JS собирает уникальные значения поля
`category` из `stock.json`, генерирует кнопки `.case-filter` (родной стиль
с `/proekty/`).

Поведение:
- Кнопка **«Все (N)»** активна по умолчанию.
- Каждая категория — отдельная кнопка с количеством `(M)`.
- Клик скрывает карточки других категорий (через `hidden`), счётчик в
  заголовке (`[data-stock-count]`) пересчитывается.
- Если категория одна — фильтр **скрывается полностью** (нет смысла).

---

## 7. Edge cases

- **Товара нет в `raw-pages/`** → `[stock] ⚠ пропускаю`, бейдж не появится,
  карточка в `/nalichie/` не появится. URL остался в config — не страшно,
  можно поправить и пересобрать.
- **На странице товара нет `<h1 class="phero__title">`** → fallback на
  `meta.title` (но без хвоста `— характеристики, цена · УралИндуктор`).
- **На странице товара нет картинки** → карточка без обложки (бейдж всё
  равно есть).
- **Пустой `stock.config.json`** → секция «Сейчас на складе» показывает
  empty-state «Пока без отдельных позиций…», заголовок `0 позиций`, бейджи
  в каталогах не появляются.
- **Кэш браузера** — `stock.json` и JS отдаются с `Cache-Control: no-cache,
  must-revalidate`, но при подозрении на старую версию — `Cmd+Shift+R`.

---

## 8. Что НЕ ломать

- Не редактировать `public/data/stock.json` руками — стереётся следующим
  `npm run build`.
- Не убирать `prebuild` из package.json.
- Не удалять `<link rel="stylesheet" href="/css/stock.css">` из
  `BaseLayout.astro` — без этого нет бейджа и категории-капшна.
- Не путать слаг (`induktsionnye-plavilnye-pechi/po-stali/ui-0-25t-250`,
  без `/products/`) и URL (полный, со слешами). В **config пиши URL**, slug
  скрипт делает сам.
