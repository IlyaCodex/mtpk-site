# Типы страниц сайта uralinduktor.ru

**Назначение этого файла:** единая карта типов страниц и ссылки на их шаблоны. Любая страница на сайте принадлежит ровно одному типу. У каждого типа — фиксированный шаблон (см. файлы T01–T12). При создании новой страницы:

1. Определи её тип по таблице ниже.
2. Открой соответствующий файл шаблона.
3. Скопируй ближайший существующий пример (указан в шаблоне).
4. Адаптируй контент.
5. Зафиксируй URL в [`structura.md`](../../structura.md).

---

## Единая терминология (соблюдать во ВСЕХ обсуждениях и документации)

| Уровень | Термин | URL-паттерн | Пример | Кол-во |
|---:|---|---|---|---|
| **L0** | Главная | `/` | https://uralinduktor.ru/ | 1 |
| **L1** | Корень каталога | `/products/` | https://uralinduktor.ru/products/ | 1 |
| **L2** | **Раздел** | `/products/<раздел>/` | `/products/induktsionnye-plavilnye-pechi/` | 12 |
| **L3** | **Категория** | `/products/<раздел>/<категория>/` | `/products/induktsionnye-plavilnye-pechi/po-stali/` | 36 |
| **L4** | **Товар** (товарная позиция) | `/products/<раздел>/<категория>/<товар>/` или `/products/<раздел>/<товар>/` | `/products/.../po-stali/ui-0-5t-400/` | 296 |

**ВАЖНО — не путать с прошлой терминологией.** До 3 июня 2026 в документации использовалось «категория → подкатегория → товар». **Теперь — «раздел → категория → товар».** В коде CSS-классы (`cat-hero`, `cat-section`) остались как есть — это технические имена, не путать с бизнес-сущностями.

Раздел = технологическая линия с набором узлов оборудования. Структура страницы отличается от продуктового — больше про процесс, узлы и комплектацию «под ключ»:

|---|---|
| `/products/oborudovanie-dlya-peschano-glinistyh-smesej-pgs/` | Линии ПГС |
| `/products/linii-dlya-holodnotverdeyushhih-smesej-hts/` | Линии ХТС |
| `/products/oborudovanie-lgm/` | Оборудование ЛГМ |
| `/products/oborudovanie-lvm/` | Оборудование ЛВМ |

Шаблон: [`T03b-section-tech.md`](T03b-section-tech.md)

## Общие компоненты на ВСЕХ страницах

Эти блоки приходят из `astro/src/layouts/BaseLayout.astro` или партиалов и **не нужно дублировать** в `raw-pages/*/body.html`:

| Компонент | Файл-источник | Что делает |
|---|---|---|
| Шапка (header) | `astro/src/components/Header.astro` | Логотип, мегаменю, утилитарная строка, поиск, CTA «Запросить КП» |
| Мобильное меню | `astro/src/components/Drawer.astro` | Слайд-аут навигация |
| Футер | `astro/src/components/Footer.astro` | Логотип, контакты, ссылки каталог/услуги/произв./компания, юридические ссылки |
| BaseLayout | `astro/src/layouts/BaseLayout.astro` | `<head>`: title, meta description, canonical, OG, JSON-LD Organization+WebSite, preload, fonts, аналитика |
| Аналитика | `astro/src/components/Analytics.astro` | Яндекс.Метрика + Roistat (через defer + requestIdleCallback) |
| Скрипты | `astro/public/js/*.js` | forms.js, mobile-nav.js, phone-mask.js, catalog-filter.js, stock-badges.js, projects-map.js |
| Стили базы | `astro/src/styles/tokens.css`, `astro/public/css/{mobile-fixes,stock}.css` | Цвета, типографика, токены, мобильные фиксы, бейджи «В наличии» |

## Правила работы со шаблонами

1. **Шаблон — обязательный контракт.** Если страница T03a (продуктовый раздел), её body.html ДОЛЖЕН содержать все обязательные блоки из шаблона. Опциональные — по контексту.
2. **CSS — через `inline_styles` в `meta.json`.** Базовый блок копируется из соседней страницы того же типа. Стили `header`/`footer`/`container` живут в этом блоке (не в BaseLayout).
3. **Формы обязательно `js-lead-form`.** См. правило #7 ниже в CLAUDE.md. Без класса и hidden-полей форма НЕ работает.
4. **При создании новой страницы того же типа** — копировать ближайший пример (указан в шаблоне), а не писать с нуля.
