## Главный вывод

Самая большая проблема — **CSS-блобы в meta.json**: 53 MB CSS на 517 страниц,
при этом 69% каждого блоба — одно и то же ядро. Чинится одной системной
правкой (вынос ядра в общий файл), а не обходом страниц. Инлайн-стили и
WP-мусор в HTML оказались мелочью.

## 1. CSS-блобы (приоритет №1)

Факты из аудита:

- 517 страниц, у каждой в `meta.json` лежит копия CSS (~100–131 KB).
- Уникальных вариантов всего **79**; три группы покрывают 399 страниц (176+125+98).
- Общее ядро — **468 правил (58 KB), есть во всех 79 вариантах** = шапка,
  футер, контейнер, кнопки и т.д., скопированные на каждую страницу.
- Сверх ядра у вариантов до ~390 своих правил (стили конкретных шаблонов:
  товар, проект, услуга).

Что это значит: правка цвета кнопки сегодня = правка в 79 местах. После
выноса ядра = правка в одном файле.

План (фаза 2, системные правки):

> ⚠️ **Каскадная ловушка (важно для В-3).** `@media`-оверрайды должны идти
> ПОСЛЕ базовых правил. Если вынести общий `@media` в site.css (грузится до
> блоба), а base-правило останется в блобе (после), поздний base переопределит
> ранний `@media` → ломается мобильная вёрстка (поймано на `.leadgen__grid`:
> мобильный grid не сворачивался в 1 колонку, секция −335px). Поэтому в site.css

> в блобах**. Эквивалентность проверяется симуляцией каскада на 7 ширинах
> (360…1500px) для старого и нового — см. скрипт.
>
> ⚠️ **Двойной билд.** `extractInlineStyles()` пишет в `public/` во время рендера,
> а Astro копирует `public/→dist/` в начале билда — новые хэши попадают в dist
> только со ВТОРОГО `npm run build`. При смене блобов всегда билдить дважды.

## 3. Мобильная версия (приоритет №2 — после запуска скрипта)

Статика мобильную не покажет — нужен браузер. Скрипт готов:

```
cd astro && npm run build        # если dist устарел
node ../scripts/mobile-audit.mjs --limit 30   # проба
node ../scripts/mobile-audit.mjs              # все 517 (~10-15 мин)
```

Что делает: открывает каждую страницу в 375px, ищет горизонтальный скролл,
для проблемных находит элемент-виновник и делает скриншот.
Результат: `docs/mobile-audit.csv` + скриншоты в `/tmp/mobile-shots/`.

- [x] **В-5 СДЕЛАНО (2026-06-05).** Починено по группам виновников в
      `public/css/mobile-fixes.css` (грузится ПОСЛЕ блобов → правит каскад
      без !important). Повторный прогон `mobile-audit.mjs`: **0 из 517**
      (было 63). Корень почти всех случаев — grid/flex-элемент с

### Итоги прогона (2026-06-05, все 517 страниц, 375px)

**63 страницы из 517** с горизонтальным скроллом. Медиана overflow — 12px
(половина — мелкие хвосты ≤15px). Один тяжёлый случай (632px). Чинится
**6 группами по виновникам**, не постранично.

Топ виновников (селектор → сколько страниц → ширина блока):

| Виновник | Страниц | Overflow | Где | Природа |
|---|---|---|---|---|
| `div.stat` | 10 + ~30 в «?» | 12–477px | запчасти (5), муфельные (2), ковши/стенд, чиллеры (24), нагреватели (5) | статблок/спеки вылезают на ~12px из-за padding; на части — крупно (>440px) |
| `div.phero__media` | 12 | 118–125px | дробемёты «для швеллера» (uid-*) | hero-фото товара ~475px не сжимается под 375px |
| `div.econ__table` | 4 | 30–40px | хабы ЛВМ / ЛГМ / ХТС / ПГС | широкая таблица «экономика» не уходит в скролл-обёртку |
| `div.case__media` | 1 | **632px** | `/o-company/` | самый тяжёлый: блок кейса 427px + что-то тянет страницу |
| `article.situation-card` | 1 | 110px | `/uslugi/remont-drobemetov/` | карточка-ситуация 465px |
| «?» (мелкие ≤15px) | 35 | 2–13px | чиллеры (24), нагреватели (5), ковши (3), press-avtomat, vakuumnoe | скрипт не назвал — блок уже экрана, но правый край вылезает на ~12px (padding/margin). Реальные: `spec__body`, `stat`, `phero__media` |

Замечания по методу:
- Эвристика скрипта ловит элементы **шире** экрана; блоки чуть уже экрана,
  но со смещённым правым краем (padding/margin) попадают в «?». При почин-ке
  проверять именно правый край (`getBoundingClientRect().right > clientWidth`).
- `aside.nav-drawer` (375px, off-canvas мобильное меню) виден почти на всех
  «?»-страницах правым краем на 395px — но на 454 страницах без overflow он
  тоже есть и клипается. Это **не** универсальный виновник, перепроверено.

Группировка для В-5 (один фикс = десятки страниц):
1. `phero__media` — `max-width:100%` / object-fit на hero-фото товара (12 стр.).
2. `stat` / `spec__body` — убрать лишний padding или дать обёртке overflow (≈40 стр.).
3. `econ__table` — завернуть таблицу в `overflow-x:auto` (4 стр.).
4. `/o-company/` `case__media` — точечно (1 стр., но самый крупный, 632px).
5. `situation-card` на `/uslugi/remont-drobemetov/` — точечно (1 стр.).

Полный список — `docs/mobile-audit.csv`; скриншоты проблемных — `/tmp/mobile-shots/`.
